# Private customer capture

The Plus host binds the authenticated customer and estimate outside the shared `/capture/` page. The page receives no access token and cannot choose an estimate ID. RPC is documented in `capture-web/INTEGRATION.md`; all API actions resolve the owned estimate again. Photo writes require a draft, while successful operation receipts remain replayable after submission.

The nine documentation views include a driver-door-jamb VIN label. These views never become priced damage panels. New bridge submissions declare `capture_version: 2`; frozen version-1 machine receipts retain their original eight-view contract. PDR pairs use `hail_close_<panel>` and `hail_raking_<panel>` and import as two images of one area. A complete pair supersedes a legacy single photo for that area before the immutable submission is created.

`POST /v1/estimates/{id}/capture/photos` accepts an 8 MB JPEG, PNG, or WebP, canonical capture key/body style, and UUID operation ID. Decoding is capped at 16 million pixels and two simultaneous decodes per process. The upload transaction reserves storage and a customer-scoped rate allowance before provider work. The older `/photos` endpoint keeps its 10 MB contract and response shape but shares the same private storage transaction and hourly upload budget; it makes no automated framing claim.

An operation owns a deterministic private file. File bytes and directory entries are synced before the database reference is committed. A lost COMMIT acknowledgment never causes those bytes to be deleted. The identical operation can recover after its one-minute lease; a changed body cannot reuse its UUID. Active-photo state reads only the exact current operation receipts, so retake history does not grow each state response. Cleanup checks that a file has no live Photo reference before removing it. Abandoned pending captures expire after a day beyond their lease; cleanup is bounded to 100 receipts per write. Replaced-file metadata remains durable so a later request can finish cleanup after an uncertain save.

Framing assistance crosses only the fixed original Estimoto bridge origin with a machine credential. Definite framing rejection preserves the previous photo; provider unavailability allows a manual save marked `not_checked`. `framing_checked` describes framing only, not damage assessment or a quote. VIN OCR reads the current private VIN image and stores a suggestion. Only explicit confirmation, bound to the current photo SHA and expected saved VIN, can change the vehicle VIN. Capture help is bounded text about the current photography step and cannot send messages or schedule repairs.

Capture receipts and VIN suggestions are private tables with RLS enabled and no public/anonymous/authenticated database grants. They are separate from customer learning records. The page has a restrictive CSP with no network connections, first-party script/frame restrictions, camera access, and no microphone access.

Validation covers owner isolation, changed-body replay, failed retakes, both possible uncertain COMMIT outcomes, the older upload route, expired staging cleanup, quotas, decoded-image bounds, OCR suggestion/confirmation races, and actual original-source versioned bridge contracts. Local tests and mocked provider checks are not live OCR, Google, browser-camera, or physical-device proof.
