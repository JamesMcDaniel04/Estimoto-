# Shared customer capture handoff

The original Estimoto guided camera and 3D vehicle guide are the authoritative source. The Plus site vendors exact source bytes with a checked-in hash manifest so a Plus-only checkout can build. The original source commit is `0729c7f4a4d153df150ccb84f606942f63a3d60d`. Change and commit original sources first, run `scripts/sync_capture_ui.sh /path/to/Estimoto`, review the generated manifest and sources, then run `scripts/build_capture.sh`. The build refuses changed vendored files.

Plus serves the standalone output at `/capture/` on the same HTTPS origin as the API. The page has no account credential, estimate identifier, or private photo URL. The embedding Flutter/web host owns the customer and estimate, translates each RPC into the owner-bound private API, and must check the owner again after each asynchronous call. See [INTEGRATION.md](INTEGRATION.md) for every method, response, error, pause and resume message. The host must preserve HTTP status in the error envelope: a definitive 422 permits a new frame, while timeout or uncertain writes must retry the same file and operation ID.

The original public intake and new Plus draft require the nine documentary views, including the driver-door-jamb VIN label. New Plus estimate submissions must send capture version 2. A persisted legacy Plus version-1 receipt may finish its frozen eight-photo intake; public links have no such exception. PDR damage requires a matching close/raking pair or a legacy panel photo. A raking photo supports assessment; the VIN photo does not price damage. OCR only suggests a VIN. The customer must inspect the physical label and explicitly confirm against the current photo ID, photo SHA-256 and saved VIN.
